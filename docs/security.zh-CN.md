# 安全边界与问题报告

## 支持范围

当前候选发行版面向可信任的本机环境和明确开启的可信局域网。默认后端、前端仅监听 `127.0.0.1`；局域网模式需要在启动器中主动启用。本项目尚未验收直接暴露到公网或作为托管多租户服务的部署方式。

维护者优先处理当前候选版本可复现的问题。历史发行版不承诺持续获得补丁，升级说明会标明必要的数据与运行环境变化。

## 报告渠道

请优先使用仓库 Security 页面提供的私密漏洞报告入口。仓库公开且维护者启用 Private vulnerability reporting 后，该入口可用。如果暂未显示入口，请在 Issue 中仅请求一个安全联系渠道，不要公开具体利用步骤、凭据或受影响用户的数据。

报告应包含版本、操作系统、最小复现条件、影响与可公开的脱敏信息。不得附 API Key、数据库连接密码、登录 Cookie、完整日志、数据库备份或用户正文；维护者不会要求在公开 Issue 中提交这些材料。

## 本地数据

运行配置位于 `backend/config/config.yaml`。`backups/`、`logs/`、`reports/`、`managed-assets/` 和 `static/` 属于本机数据，源码发布包不包含这些目录。开启诊断或分享备份前应确认内容范围；完整数据库备份含本地账号的密码哈希与小说所有权记录，应按私密文件保存。

付费模型调用需要用户显式授权。全库恢复遇到执行中的任务、调用预留或尚未确认的用量时会拒绝恢复；恢复成功后，旧生成授权失效，继续生成需重新预检并授权。安全快照保留恢复前的账本证据。

## 发布检查

发行前检查锁定依赖的公开安全公告、源码中可能的凭据、打包排除规则及隔离环境验证结果。扫描只针对其覆盖范围，不能证明软件不存在其他漏洞。历史 Git 对象须单独检查，不能用当前源码扫描通过代替历史清理。
