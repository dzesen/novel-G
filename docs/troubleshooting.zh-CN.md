# 安装与日常使用排错

先从当前界面或安装终端给出的错误入手。安装步骤见[源码包说明](source-release.zh-CN.md)，创作操作见[使用指南](user-guide.zh-CN.md)。

## 安装未完成

确认使用 Windows 10/11、64 位 Python 3.11/3.12（含 Tcl/Tk）、Node.js 22.x（至少 22.13）或 24 LTS，以及 MongoDB 7/8。修改 PATH 或重新安装运行环境后，重新打开终端或批处理入口。

`setup.bat` 会先检查环境，再安装依赖和构建前端。网络问题或步骤失败后，修正原因并重新运行，已验证的成功步骤可复用。进入安装脚本后的日志保存在 `logs/installation/`。

| 情况 | 处理方式 |
| --- | --- |
| 没有 Python、Node.js 或 npm | 安装支持的运行环境，重新打开 `setup.bat` |
| 已有 `.venv` 的 Python 不兼容 | 关闭服务，保留并重命名旧 `.venv`，再运行安装；脚本不会自动删除它 |
| 依赖安装或下载失败 | 根据本次安装日志修正网络、权限或环境问题，再运行 `setup.bat` |
| 依赖已完成，但 MongoDB 未就绪 | 启动 MongoDB 或修正连接配置，再运行 `setup.bat --check` |
| 需要重新安装依赖和构建 | 关闭服务后运行 `setup.bat --repair` |

退出码 `0` 表示就绪，`1` 表示安装或检查失败，`2` 表示依赖与构建已完成，但 MongoDB 或本地配置仍需处理。

## 启动器未打开，或页面未出现

先运行以下检查。

```powershell
.\setup.bat --check
```

检查会生成本地日志，首次配置检查可创建默认配置，不下载依赖或重新构建。启动器初始化失败的日志位于 `logs/launcher-startup.log`。

默认启动顺序为后端、前端、打开工作台，每个服务阶段最多等待 90 秒。检查启动器中对应服务的日志；修正问题后可点击“全部启动”重试。工作台默认地址为 `http://127.0.0.1:3000`，后端为 `http://127.0.0.1:8000`。

端口被其他程序占用时，启动器会停止启动，不会终止未知进程。先确认占用者，再由你决定是否关闭该程序。需要先选择模式时，运行 `start.bat --manual`。

## 模型或生成预检不能通过

在管理员设置页检查对应工作流使用的提供商、模型、连接地址、输出 Token 上限和结构化输出能力。已有其他模型能工作，不代表当前工作流使用的是同一配置。

预检本身不产生付费调用。容量或额度不足时，调整生成范围、模型能力或预算，再重新预检；不要把旧确认当作新设置的授权。模型连通性和能力测试需要你显式触发。

## 任务暂停或正文未完成

优先查看当前任务的暂停原因及处理入口。新资料可能需要审核或重新确认世界资料基线；分场计划和输出风险需在当前弹窗中处理。不要用反复启动代替这些决策。

未完成草稿保留场景进度，可在章节工作区显式恢复。只有完整正文才能进入完成链。使用“不审查”保存完整草稿后，状态回填仍需单独进行；这不表示保存失败。

如果用量尚未确认，先在恢复入口处理该请求。未确认用量会阻止某些恢复与备份恢复操作，重新启动应用不会自动消除它。

## 状态、备份与诊断

在项目目录运行只读诊断。

```powershell
.\.venv\Scripts\python.exe -m backend.diagnostics
```

诊断汇总需处理的作业、状态与恢复问题，不包含正文或 API Key。退出码 `0` 表示没有待处理动作，`2` 表示报告已生成但有人工处理项，`1` 表示命令失败。按报告对应入口处理，避免直接修改数据库。

数据库备份不能替代 `backend/config/config.yaml`、`managed-assets/` 和 `static/` 的文件备份。升级和恢复前保留这些内容，详细顺序见[安装与升级](source-release.zh-CN.md)。

安装包不携带维护者的内部回归用例，安装检查使用 `setup.bat --check`；公开源码的编译、构建和运行时检查见[贡献指南](contributing.zh-CN.md)。完整业务回归由维护者在开发环境中执行。

报告问题时提供版本、操作步骤和脱敏错误摘要。不要在公开 Issue 附 API Key、数据库连接密码、登录 Cookie、完整日志、数据库备份或用户正文。详见[安全说明](security.zh-CN.md)。
