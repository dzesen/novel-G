# 源码包安装、升级与复现

当前源码版本为 `0.1.0-rc.3`，采用 [AGPL-3.0](../LICENSE)，源码包包含许可证与来源说明，具体见[许可证与来源](license-status.zh-CN.md)。包内不含 `.git` 历史、本机配置、账号、数据库、小说、日志、备份、图片资产或已经安装的运行环境。

## 新安装

1. 安装 Windows 10/11 上的 64 位 Python 3.11 或 3.12、Node.js 22.13+ 或 24 LTS、MongoDB 7/8。推荐使用最新维护补丁版本。Python 安装时包含 Tcl/Tk 并加入 PATH。
2. 启动 MongoDB，默认连接地址为 `mongodb://localhost:27017`。
3. 把 ZIP 解压到可写的独立目录，进入包含 `setup.bat` 的文件夹，再双击该文件。首次安装需要网络：先一次检查 Python、Node.js、npm 和源码完整性，再创建 `.venv`、安装固定依赖并生成前端生产构建。
4. 双击 `start.bat`，启动器会自动等待后端就绪，再启动前端；两者健康检查通过后打开工作台。首次打开时创建初始管理员。
5. 手动写作无需 API Key。需要模型功能时，由管理员在设置页配置 Provider，检查预检与费用范围后显式开始调用。

安装与启动两个批处理入口都支持 `--no-pause`。本包不含 Python / Node.js / MongoDB，不是免环境的便携程序。Git 只在重新制作发行包时需要，安装和使用无需 Git。

Node.js 20 和 23 不在此候选包的支持范围。最低版本提高到 22.13，是为了兼容锁定的前端与构建工具依赖；启动器、安装入口和前端 engines 已统一。

## 安装失败、重复安装与检查

进入 Python 安装脚本后，每次运行的独立日志保存在 `logs/installation/`，命令行会显示路径。成功步骤的校验记录保存在 `reports/installation/state.json`。修正网络或环境问题后，再次双击 `setup.bat`，会检查并复用成功的步骤。依赖清单、前端源码、前端环境文件或 `NEXT_PUBLIC_*` 构建变量变化时，会重新执行受影响的步骤；产物缺失或检查失败也会重新安装／构建。

```powershell
.\setup.bat --check
.\setup.bat --repair
.\start.bat --manual
```

- `--check` 检查现有安装和 MongoDB，不下载依赖或重新构建。检查仍会生成本地日志；首次配置检查可创建默认配置文件。
- `--repair` 在关闭服务后重新安装依赖并构建，保留本机配置、小说和文件资产。现有 `.venv` 的 Python 不兼容时，脚本要求先重命名该目录，不自动删除。
- `start.bat --manual` 只打开启动器，之后可手动选择模式并点击“全部启动”。默认双击会自动启动；每个阶段最多等待 90 秒，失败原因显示在对应服务日志中。

在同一启动器中连续点击“全部启动”不会重复派发或重复打开浏览器；“全部停止”和关闭窗口会取消尚未完成的启动。已识别的 Novel-G 服务可复用，未知端口占用会阻止启动，不会被终止。

安装退出码 `0` 表示环境就绪；`1` 表示安装或检查失败；`2` 表示依赖与构建已完成，但 MongoDB 或本地配置尚未就绪。遇到 `2` 时，启动 MongoDB／修正配置后运行 `setup.bat --check` 即可，不必重装依赖。取消安装后可重新运行继续。安装校验记录用于加速本机重试，不是文件安全审计或完整环境打包。

## 升级现有安装

先停止本机生成任务并处理未确认用量，完成全库备份；再关闭启动器管理的前后端服务。将新包解压到一个新目录，运行新目录的 `setup.bat`。不要把新包直接覆盖到仍运行的旧目录。

保留原 `backend/config/config.yaml` 并按需复制到新安装；同时保留 `managed-assets/`、`static/`、`backups/` 等本地文件。数据库备份不能代替本机配置和文件资产的备份。连接原 MongoDB 时需确认数据库名称与连接地址。新程序启动会迁移兼容配置并初始化索引。

全库恢复需要作业静止；恢复成功会停用快照中的旧生成授权，必须重新预检并授权。歧义势力身份或旧关系仍需人工复核。数据库快照一致性锁只覆盖共享同一项目锁目录的新版进程，无法协调外部数据库写入者。

`config.yaml` 含凭据，只在自己的设备间安全迁移，不要放进 GitHub、Issue 或发布附件。

## 校验包

对 ZIP 运行：

```powershell
Get-FileHash -Algorithm SHA256 .\novel-g-0.1.0-rc.3-source.zip
```

使用项目打包器生成的源码包时，将结果与同目录 `SHA256SUMS.txt` 比较；GitHub 的 Code → Download ZIP 不附带这两份打包元数据。打包器生成的包内 `RELEASE-MANIFEST.json` 记录 Git commit、分发状态、每个文件的大小与 SHA-256。Windows 批处理统一为 CRLF。安装包的环境检查使用 `setup.bat --check`；完整回归测试在私有开发库执行，见[贡献指南](contributing.zh-CN.md)。

## 包含的文件

本包只收录应用源码、依赖清单、安装启动入口与用户文档。内部规格、过程记录、排查和模型验收材料、开发测试及夹具不随包分发。生产代码仍依赖的模块继续保留。

用户文档覆盖安装、创作、排错、使用局限、安全、许可与版本说明；新增文档必须进入明确清单后才可分发。打包器会拒绝指向未收录文件的本地文档链接。清单记录收录文件的摘要与排除数量，不列出内部材料名称。

## 从 Git 复现包

在干净且已提交的 Git 源码检出中，使用 Python 标准库即可：

```powershell
python scripts/build_release.py --output-dir dist\0.1.0-rc.3
```

打包器读取提交对象，忽略工作区本机数据；默认 HEAD 有未提交变更时拒绝打包。`--preview` 用于生成 `-review.zip` 私有评审包，清单标记 `private-review`。包含 LICENSE 的当前提交也支持普通源码模式；省略 `--preview` 并选择新的空输出目录，会生成 `-source.zip`，清单记录 `AGPL-3.0-only` 及 `source-release`。打包本身不会公开仓库或上传附件。已有产物不会覆盖。

Git 源码导出遵守同一收录边界。源码归档不携带 Git 历史；公开仓库中的文件和历史须另外检查，不能依靠归档排除规则隐藏内容。早期评审归档保留生成时的内容和校验值，新源码包从当前提交重新制作。
